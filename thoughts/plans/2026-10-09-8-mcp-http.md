# MCP: Streamable HTTP transport

## Goal
Let a remote MCP client (a cloud Claude Code session, a Claude connector) drive the phone, not only a client on the Mac the phone is plugged into. `iphone-agent/src/mcp.ts` gains `--http [port]`, served with the MCP SDK's Streamable HTTP server transport on `node:http`. This server controls a physical phone, so the point of the ticket is safe defaults: loopback only unless asked, a bearer token for anything else, read-only when exposed, and DNS-rebinding protection. Closes #8 (parent #3).

## Current state
- `iphone-agent/src/mcp.ts:28` `createPhoneMcpServer(device, { readOnly, approve })` builds a low-level `Server`; read-only hides and refuses every tool in `ACTIONS` (`mcp.ts:29`, `:47`).
- `mcp.ts:73-79` entrypoint: stdio only, `--mock`, `WDA_URL`, `IPHONE_MCP_READ_ONLY=1`.
- SDK 1.32.1, `server/streamableHttp.d.ts`: `StreamableHTTPServerTransport` wraps the web-standard transport for `node:http` (`handleRequest(req, res)`). Stateless mode is `sessionIdGenerator: undefined`. It caps POST bodies at 4 MiB (`maxRequestBodySize`).
- The transport's `allowedHosts` / `allowedOrigins` / `enableDnsRebindingProtection` options are `@deprecated` ("use external middleware"); the SDK's middleware (`server/middleware/hostHeaderValidation.js`) is Express-only. We don't add Express, so we validate Host and Origin ourselves, with the same port-agnostic `new URL("http://" + host).hostname` parse.
- A `Server` connects to one transport, so stateless mode needs one `Server` + transport per request (the SDK's documented stateless pattern). The `Device` (and its WDA session) is shared.
- Constraints: strip-types syntax, strict tsconfig, no new runtime deps. `agent.ts` is off limits (another ticket edits it).

## Out of scope
- OAuth / the MCP authorization spec. A static bearer token is enough for a single-user tunnel.
- TLS termination (Tailscale encrypts the tunnel; `tailscale serve` can add HTTPS).
- Stateful sessions, resumability, server-initiated notifications (GET returns 405).

## Phase 1: loopback HTTP transport
### Changes
- `iphone-agent/src/mcp-http.ts` (new): `startPhoneHttpServer(device, opts)` -> `{ url, readOnly, close }`. `node:http` server on `127.0.0.1`, only `/mcp`, per-request stateless `Server` + `StreamableHTTPServerTransport`. Host/Origin validation against loopback names.
- `iphone-agent/src/mcp.ts`: `--http [port]` (default 8765) picks the HTTP mode; stdio stays the default and unchanged.

## Phase 2: exposure beyond localhost
### Changes
- `mcp-http.ts`: `host` option. A non-loopback bind throws unless a token of at least 32 characters is given. When a token is set (any bind), every request needs `Authorization: Bearer <token>`, compared with `crypto.timingSafeEqual` over SHA-256 digests (equal length, no length leak); otherwise 401 with `WWW-Authenticate: Bearer`. Non-loopback bind is read-only unless `allowActions`. Allowed Host names: loopback names, the bind address (unless a wildcard), plus `allowedHosts` (for a MagicDNS name).
- `mcp.ts`: `--host <addr>`, `--allow-actions`, `--allowed-host <name>` (repeatable), token from `IPHONE_MCP_TOKEN`. Refuses to start with a non-zero exit and a stderr message.
- `iphone-agent/README.md`: HTTP mode, flags, Tailscale tunnel recipe instead of opening ports.
### Success criteria
Automated:
- [ ] tests: no token -> 401, wrong token -> 401, right token -> tools listed
- [ ] test: non-loopback bind without token refuses to start (function and CLI)
- [ ] test: non-loopback bind is read-only without `allowActions`, full with it
- [ ] root `npm test`, root `tsc -p .`, `bash scripts/anti-slop.sh`
Manual:
- [ ] On the Mac: `IPHONE_MCP_TOKEN=... npm run mcp -- --http --host <tailscale-ip>`, then `claude mcp add --transport http iphone http://<tailscale-ip>:8765/mcp --header "Authorization: Bearer ..."` from another machine on the tailnet; screenshot works, tap is absent.

## Risks & rollback
- Mis-configured exposure is the main risk; the defaults fail closed (refuse to start, read-only, 401/403). Stdio is untouched, so reverting the PR removes HTTP mode with nothing stateful left behind.

## Review follow-ups (same PR)
- "Exposed" = non-loopback bind OR any non-loopback `--allowed-host` (proxy in front of loopback): token required, read-only unless `--allow-actions`.
- Tool calls serialized per device in `createPhoneMcpServer` (shared across per-request servers); reads included so a screenshot never lands mid-action. Approval stays outside the lock.
- `--allowed-host` / `--host` validated and canonicalized (no scheme/port/path/whitespace; lowercase, trailing dot dropped, IPv6 via WHATWG URL); bracketed IPv6 stripped before `listen()`.
- `--http=<port>` accepted; HTTP-only flags without `--http` exit 1. Any 127.0.0.0/8 Host is loopback. 500s return a generic JSON-RPC internal error, details to stderr. MCP tool list built once per process.
